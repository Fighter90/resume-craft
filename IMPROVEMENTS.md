## 3. Внедрённые улучшения

По итогам тестирования и обратной связи были внедрены следующие исправления:

### 3.1. AVATAR-DELETE-503 — Исправлено удаление аватара (P2)

**Проблема:** DELETE /api/v1/auth/me/avatar возвращал 503. UI не показывал ошибку пользователю (silent failure). Фокус-группа отмечала непредсказуемое поведение аватара.

**Что сделано:**

- Исправлена обработка ошибок в endpoint: при сбое БД выполняется rollback и возвращается JSON-ответ с понятным сообщением вместо необработанного исключения.
- Endpoint теперь всегда завершает операцию корректным HTTP-ответом (204 при успехе, 500 с сообщением при сбое).

**Файл:** src/app/auth/router.py

### 3.2. AVATAR-DELETE-BTN-UX — Скрыта кнопка удаления аватара без аватара (P4)

**Проблема:** Кнопка «Удалить» аватар отображалась даже когда аватар не загружен.

**Что сделано:**

- Кнопка теперь полностью скрыта, если аватар не загружен (вместо disabled-состояния).

**Файл:** frontend/src/pages/settings/SettingsProfilePage.tsx

### 3.3. VACANCY-URL-500 — Добавлена серверная валидация URL вакансии (P3)

**Проблема:** Невалидный URL вакансии (не hh.ru) вызывал 500 Internal Server Error. Пользователь получал общую серверную ошибку вместо понятного сообщения.

**Что сделано:**

- Добавлен перехват ValueError при извлечении ID вакансии из URL.
- Невалидный URL теперь возвращает 400 Bad Request с сообщением «Введите корректную ссылку на вакансию hh.ru».
- Поведение унифицировано с валидацией ссылки на резюме hh.ru.

**Файл:** src/app/vacancies/service.py

### 3.4. SECURITY-AUTOFILL — Исправлено автозаполнение паролей (P4)

**Проблема:** Браузер автозаполнял парольные поля на странице безопасности. Пользователь видел якобы заполненные поля.

**Что сделано:**

- Поле «Текущий пароль» — атрибут изменён с autocomplete="off" на autocomplete="current-password".
- Поле пароля при удалении аккаунта — атрибут изменён с autocomplete="new-password" на autocomplete="current-password".

**Файл:** frontend/src/pages/settings/SettingsSecurityPage.tsx

### 3.5. GROQ-MODEL-NAME-HISTORY — Исправлено отображение модели Groq (P4)

**Проблема:** В истории оптимизаций Groq отображался как «Groq» без названия модели, тогда как остальные провайдеры показывали формат «Провайдер · Модель».

**Что сделано:**

- Добавлен провайдер 'groq' в условие сохранения sub-model при записи результата оптимизации.
- Теперь Groq сохраняется в формате «groq:model-name» аналогично OpenAI, Anthropic и OpenRouter.

**Файл:** src/app/rewriter/service.py

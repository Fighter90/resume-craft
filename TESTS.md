# ResumeCraft — TESTS

> Дата: 13.03.2026
> Статус: результаты технического и пользовательского тестирования

---

## 1. Цель документа

Документ фиксирует результаты тестирования сервиса ResumeCraft двух типов:

1. **Техническое тестирование** — проверка функциональности сервиса в production-среде по сценариям реального использования.
2. **Пользовательское тестирование** — сбор и анализ обратной связи от небольшой обезличенной фокус-группы.

---

## 2. Методика

### 2.1. Техническое тестирование

Проверка охватывала полный пользовательский flow:

- регистрация и авторизация;
- настройка API-ключей для 5 AI-провайдеров;
- оптимизация резюме каждым провайдером;
- экспорт в DOCX, PDF, TXT;
- история оптимизаций и лимиты Free-плана;
- профиль, настройки безопасности;
- поиск и загрузка вакансий hh.ru;
- загрузка резюме (текст, файл, ссылка hh.ru);
- дашборд.

Всего выполнено **27 тестов**.

### 2.2. Пользовательское тестирование

Обратная связь собрана от четырёх обезличенных респондентов фокус-группы (источник: test.pdf). Формат — exploratory feedback по реальным сценариям использования.

### 2.3. Ограничения

- Размер фокус-группы малый — выводы применимы для качественного UX-анализа, не для статистически значимого исследования.
- Отдельные сценарии не удалось полноценно проверить из-за ограничений среды (например, загрузка реального резюме hh.ru).

- OpenAI — самый слабый прирост и самое долгое время ответа.

## 4. Результаты пользовательского тестирования

### 4.1. Фокус-группа

Четыре обезличенных респондента (test.pdf). Формат — exploratory feedback по реальным сценариям.

Размер группы достаточен для выявления повторяющихся UX-паттернов:

- потеря ориентации в навигации;
- неочевидные системные сообщения;
- слабая обратная связь на действия пользователя;
- недоверие к результату при несогласованности интерфейса.

### 4.2. Наблюдения фокус-группы

| Категория | Наблюдение | Статус |
| --------- | ---------- | ------ |
| Навигация | Переход в тарифы воспринимается как выход из основного сценария без возврата | Требует перепроверки |
| Авторизация | Неинформативные сообщения об ошибках при регистрации/входе | Требует перепроверки |
| Авторизация | Ошибка из одной вкладки может визуально переноситься в другую | Требует перепроверки |
| Flow | Долгая загрузка и нестабильный возврат при работе с GigaChat | Частично подтверждено как UX-риск |
| Контент | Знак $ воспринимается как цена в долларах | Требует перепроверки |
| Экспорт | Возможны проблемы с кодировкой PDF | Требует перепроверки |
| Экспорт | В некоторых сценариях обрезается выпадающий список форматов | Требует перепроверки |
| Вакансии | Пагинация вакансий может не обновлять список визуально | Требует перепроверки |
| Вакансии | Фильтр «Удалённо» может возвращать офисные вакансии | Требует перепроверки |
| Профиль | Удаление фото применяется без явного подтверждения | Коррелирует с AVATAR-DELETE-503 |
| Профиль | Город и телефон ранее не сохранялись | Исправлено ранее |
| Безопасность | Формулировка «опасная зона» воспринимается как лишняя | Продуктовое улучшение |
| Дашборд | Карточки дашборда хочется сделать кликабельными | Улучшение UX |
| Настройки AI | Неочевидно, что нужен собственный API-ключ; выбор модели путает | Требует UX-доработки |
| Результаты | В описании вакансии после парсинга могут оставаться HTML-теги | Требует перепроверки |

### 4.3. Ключевые UX-паттерны

**Паттерн 1. Потеря контроля над состоянием интерфейса.**
Непонятно, сохранилось ли изменение; кнопка визуально есть, но результат непредсказуем; возврат назад ощущается нестабильно. Снижает доверие до оценки качества AI-результата.

**Паттерн 2. Ограничения продукта не объяснены заранее.**
Неочевидно, что нужны собственные API-ключи; неочевидно, что часть функций работает в ограниченном режиме. Пользователь воспринимает ограничение как поломку.

**Паттерн 3. Сумма мелких дефектов создаёт впечатление сырого продукта.**
По отдельности автозаполнение паролей, отсутствие модели Groq в истории, некликабельные карточки — мелочи. Но вместе ухудшают ощущение качества при демонстрации.

### 4.4. Что уже было закрыто до тестирования

- Сохранение телефона и города.
- Повторная отправка подтверждения email.
- Валидация формы удаления аккаунта.
- Маска ввода телефона.
- Описание экспортных форматов.
- Клиентская валидация hh.ru-ссылки для резюме.

## 5. Общая оценка

### 5.1. Сильные стороны

- Основной бизнес-сценарий работает end-to-end.
- Все 5 AI-провайдеров стабильны.
- Экспорт закрывает практическую задачу пользователя.
- История, лимиты и профиль стабилизированы.

### 5.2. Зоны риска

- Несогласованность обратной связи интерфейса в ошибочных сценариях.
- Остаточные проблемы ясности onboarding и AI-настроек.
- Мелкие UX-несоответствия, влияющие на восприятие качества.

### 5.3. Вывод

ResumeCraft прошёл проверку как рабочий MVP с устойчивым основным сценарием. Пользовательское тестирование подтвердило, что ценность сервиса понятна, но впечатление о качестве зависит от прозрачности ошибок и аккуратности UX-деталей.

По итогам тестирования выявлено 5 конкретных дефектов, которые были исправлены (см. IMPROVEMENTS.md). Остальные наблюдения фокус-группы зафиксированы как backlog на следующую версию продукта.

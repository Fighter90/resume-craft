# ResumeCraft: фундаментальное исследование для AI-реврайтера резюме

**ResumeCraft может занять пустующую нишу на российском рынке AI-сервисов для соискателей.** При 93+ млн резюме на hh.ru, росте конкуренции за вакансии на 25% год к году и отсутствии полноценного русскоязычного AI-реврайтера, проект обладает значительным рыночным потенциалом. Ни один из глобальных лидеров (Rezi, Jobscan, Resume Worded) не поддерживает русский язык, а российские аналоги (Cvator.ru, Rezumus.com) находятся на ранней стадии развития. Технологический стек FastAPI + PostgreSQL/pgvector + LLM API (GigaChat/YandexGPT для продакшена, Groq/Ollama для разработки) позволяет создать MVP с минимальным бюджетом **$0–15** за весь проект.

## 1. HeadHunter API открывает доступ к крупнейшей базе вакансий

Официальная документация HH API размещена в GitHub-репозитории **github.com/hhru/api** (~590 звёзд, 756+ коммитов, активно поддерживается). Документация доступна на русском (`docs/`) и английском (`docs_eng/`), а интерактивная спецификация — на api.hh.ru/openapi/redoc.

**Базовый URL**: `https://api.hh.ru`. API использует REST-архитектуру, все ответы — JSON, даты в формате ISO 8601. Ключевые endpoints для проекта:

| Endpoint | Метод | Авторизация | Назначение |
|----------|-------|-------------|------------|
| `/vacancies` | GET | Не требуется | Поиск вакансий по тексту, региону, зарплате, опыту |
| `/vacancies/{id}` | GET | Не требуется | Детали вакансии: описание, требования, зарплата, работодатель |
| `/resumes/mine` | GET | OAuth 2.0 (applicant) | Список резюме авторизованного пользователя |
| `/resumes/{id}` | GET/PUT | OAuth 2.0 | Чтение и редактирование резюме |
| `/dictionaries` | GET | Не требуется | Справочники: опыт, занятость, графики, валюты |
| `/professional_roles` | GET | Не требуется | Профессиональные роли (замена specializations) |
| `/skills` | GET | Не требуется | Справочник навыков |

Авторизация реализована через **OAuth 2.0** с четырьмя уровнями доступа: анонимный (поиск вакансий), приложение (client_credentials), соискатель и работодатель. Регистрация приложения на dev.hh.ru выдаёт `client_id` и `client_secret`. Access-токен живёт **~14 дней**, обновляется через refresh-токен.

Для ResumeCraft критически важно: **данные о вакансиях свободно доступны** без авторизации — можно извлекать описания должностей, требуемые навыки и опыт для AI-оптимизации резюме. Параметры поиска включают `text` (поддерживает язык запросов hh.ru), `area` (регион), `experience`, `salary`, `schedule` (включая `remote`). Ответ содержит полное описание вакансии с полями `description`, `key_skills`, `experience`, `employment`, `salary`.

**Ограничения**: пагинация ограничена **2000 результатами** суммарно; `per_page` максимум **100**; обязателен заголовок `User-Agent` с идентификацией приложения; при превышении лимитов — HTTP 429. Работа с базой резюме работодателей — **платная функция**. Для интеграции с ResumeCraft потребуется только бесплатный доступ к вакансиям и OAuth-авторизация соискателя для чтения его собственных резюме.

Пример запроса на Python:
```python
import requests
headers = {'User-Agent': 'ResumeCraft/1.0 (contact@example.com)'}
params = {'text': 'Python developer', 'area': '1', 'per_page': 20}
response = requests.get('https://api.hh.ru/vacancies', headers=headers, params=params)
```

## 2. Конкурентный ландшафт: глобальные лидеры против пустого российского рынка

### Глобальные сервисы не работают с русским языком

Пять ведущих мировых AI-сервисов резюме демонстрируют зрелый рынок с чёткой специализацией:

| Сервис | Ключевая фича | Цена (мес.) | ATS-оптимизация | Русский язык |
|--------|--------------|-------------|-----------------|--------------|
| **Rezi.ai** | Таргетинг по ключевым словам, скоринг 1–100 | $29 (Pro), $149 lifetime | Лучшая в классе | ❌ |
| **Jobscan** | Reverse-engineering ATS (Taleo, Greenhouse) | $49.95 | Тестируется на реальных ATS | ❌ |
| **Kickresume** | 40+ шаблонов + GPT-4/5, бесплатно для студентов | $8–19/мес (годовой) | Хорошая | ⚠️ Частично |
| **Teal** | All-in-one: резюме + трекер вакансий + Chrome ext. | $29 (Plus) | Хорошая | ❌ |
| **Resume Worded** | Скоринг 1–100 по 30+ критериям, LinkedIn-оптимизация | $49 | Хорошая | ❌ |

**Ни один глобальный лидер не предлагает полноценной поддержки русского языка и интеграции с hh.ru.** Дополнительный барьер — российские банковские карты не принимаются из-за санкций. Это создаёт структурную возможность для локального продукта.

### Российский рынок: ранняя стадия с минимальной конкуренцией

Наиболее релевантные российские сервисы:

**Cvator.ru** — наиболее функциональный российский AI-конкурент. Предлагает AI-конструктор резюме, анализ соответствия вакансии (вставка ссылки hh.ru), 10 ATS-протестированных шаблонов, AI-генерацию профессионального фото, тренажёр собеседований. Экспорт в формат hh.ru. Относительно новый, ограниченное количество отзывов.

**Rezumus.com** — позиционируется как «первый русскоязычный сервис создания резюме с ИИ». Создан HR-специалистом с 10-летним опытом. Нейросеть обучена на формулировках российского рынка труда. Ценообразование: бесплатно (5 AI-запросов) → 990₽ → 2990₽ → 9990₽ (с HR-консультацией). **Не позволяет загружать существующее резюме** — критический недостаток.

**hh.ru** — доминирующая платформа с базовым конструктором резюме (1 шаблон, без AI для соискателей). AI-ассистент hh.ru запущен в бета-режиме в конце 2025 года, но **исключительно для работодателей** — помогает рекрутерам искать кандидатов, анализировать резюме, сортировать отклики. Для соискателей AI-инструментов нет — это и есть **ключевой gap**, который может заполнить ResumeCraft.

**MyResume.ru**, **ICanChoose.ru**, **CVzilla.ru**, **Shablonium.online** — шаблонные конструкторы без AI. **НейроТекстер** — общая AI-платформа с адаптацией для резюме (от 163₽/мес). Человеческие услуги: Profi.ru (от 1500₽), Kwork (от 500₽), GoodStage (5500₽ за резюме).

### Конкурентные преимущества ResumeCraft

ResumeCraft может стать первым полноценным русскоязычным AI-реврайтером, объединив функциональность Rezi + Jobscan для российского рынка: **deep AI rewriting** (не просто шаблоны), **matching с вакансиями hh.ru**, **ATS-оптимизация для российских систем** (Huntflow, Potok, Talantix), **оплата российскими картами**, работа **без VPN**. Оптимальная ценовая точка — **300–2000₽/мес**, между бесплатными инструментами hh.ru и дорогими HR-консультантами.

## 3. Парсинг PDF и DOCX: выбор технологического стека

### PDF-библиотеки: скорость против лицензии

Сравнительное тестирование (py-pdf/benchmarks, 2025) показывает драматические различия в производительности:

| Библиотека | Время (14 PDF) | Лицензия | Таблицы | OCR | Рекомендация |
|------------|---------------|----------|---------|-----|--------------|
| **PyMuPDF** (fitz) | **0.1 с** | AGPL 3.0 / Commercial | ✅ | ✅ (Tesseract) | Лучший выбор при допустимой лицензии |
| **pdfplumber** | 9.5 с | MIT | ✅ Лучший | ❌ | Лучший для таблиц + MIT |
| **pypdf** (ex-PyPDF2) | 4.2 с | BSD 3-Clause | ❌ | ❌ | Простые PDF |
| **pdfminer.six** | 7.4 с | MIT | ❌ | ❌ | Основа pdfplumber |

**PyMuPDF** — технически лучший: в **40–100 раз быстрее** pdfplumber, отличное качество извлечения текста, встроенная поддержка OCR через Tesseract, расширение **pymupdf4llm** генерирует чистый Markdown за ~0.12 с. Главный риск — **лицензия AGPL 3.0** требует открытия исходного кода или покупки коммерческой лицензии у Artifex.

**pdfplumber** — лучший выбор при MIT-лицензии. Построен поверх pdfminer.six, обеспечивает **лучшее в классе извлечение таблиц** (critical: многие резюме используют таблицы для двухколоночной верстки). Позиционные данные каждого элемента позволяют реализовать сложную логику определения секций. Скорость ~0.1 с на страницу — для единичного резюме незаметно.

**Для учебного проекта** рекомендуется **PyMuPDF** (AGPL допустима для open-source учебного проекта). Для коммерциализации — переход на **pdfplumber**.

### DOCX: python-docx как безальтернативный выбор

**python-docx** (MIT, v1.2.0) — единственная библиотека, обеспечивающая полный цикл **чтение + запись** DOCX. Это критически важно для реврайтера: после AI-обработки нужно сгенерировать новый DOCX-файл. Библиотека даёт доступ к параграфам, стилям (определение заголовков секций «Опыт», «Образование»), форматированию (жирный, курсив), таблицам.

Дополнительно **docx2python** (MIT) — для read-only извлечения с лучшим сохранением структуры (вложенные списки: документ → таблицы → строки → ячейки). **docx2txt** — fallback для простого текста.

### Рекомендуемый pipeline парсинга резюме

Современный подход 2025–2026 годов комбинирует классическое извлечение текста с **LLM-структуризацией**:

1. **Определение формата** → PDF/DOCX по расширению или magic bytes
2. **Извлечение текста** → PyMuPDF (`page.get_text()`) для PDF; python-docx для DOCX
3. **OCR fallback** → если текст пуст/нечитаем → `page.get_pixmap()` → pytesseract (300 DPI)
4. **LLM-структуризация** → отправка текста в GPT-4o-mini/GigaChat с Pydantic-схемой:

```python
class Resume(BaseModel):
    name: str
    email: Optional[str]
    phone: Optional[str]
    summary: Optional[str]
    experience: List[Experience]  # position, company, dates, description
    education: List[Education]    # degree, institution, year
    skills: List[str]
```

5. **Валидация** → Pydantic проверяет ответ LLM; retry при ошибке

Этот подход из arXiv 2510.09722 показывает **240–300 резюме/мин** при латентности ~1.54 с на резюме в продакшене. Для ResumeCraft ожидаемое время полной обработки: **2–20 секунд** (от простого PDF до OCR-скана).

## 4. Архитектура MVP: FastAPI как оптимальный фреймворк

### Почему FastAPI, а не Django или Streamlit

**FastAPI** — оптимальный выбор для AI-приложения с длительными LLM-вызовами (5–30 секунд). Нативная поддержка async/await предотвращает блокировку при ожидании ответов от OpenAI/GigaChat. Встроенная валидация Pydantic идеально ложится на структурированные данные резюме. Автогенерация Swagger UI — преимущество на защите магистерской.

**Django** избыточен для MVP: ORM и админка добавляют сложность без пользы. **Streamlit** перезапускает весь скрипт при каждом взаимодействии и не поддерживает аутентификацию — подходит только как **demo-фронтенд** для защиты, вызывающий FastAPI-бэкенд по HTTP. **Gradio** слишком узок (input→output формат).

### Рекомендуемая архитектура

```
Streamlit UI (demo) / React SPA (production)
        ↓
    Nginx (reverse proxy, SSL)
        ↓
    FastAPI Application
    ├── Auth Module (JWT/OAuth2)
    ├── Resume API (CRUD, upload)
    ├── Vacancy API (hh.ru integration)
    └── Rewrite API (LLM tasks)
        ↓                    ↓
  PostgreSQL + pgvector    Celery + Redis
        ↓                    ↓
  MinIO (файлы)          LLM API (GigaChat/YandexGPT/OpenAI)
```

**Ключевые технологические решения:**

- **PostgreSQL 16 + pgvector** — реляционные данные и векторный поиск в одной БД. Эмбеддинги резюме и вакансий хранятся в колонках `VECTOR(1536)` с HNSW-индексом для быстрого approximate nearest neighbor поиска. Это позволяет находить наиболее релевантные вакансии для резюме SQL-запросом: `ORDER BY resume.embedding <=> vacancy.embedding LIMIT 5`.

- **Celery + Redis** — асинхронная обработка LLM-задач. Пользователь загружает резюме → FastAPI создаёт Celery-задачу → возвращает `task_id` мгновенно → worker обрабатывает через LLM → результат в БД → фронтенд поллит `/tasks/{task_id}/status`.

- **MinIO** (S3-совместимое хранилище) для оригинальных файлов. В продакшене заменяется на Yandex Object Storage.

- **JWT-аутентификация** через `OAuth2PasswordBearer` (встроена в FastAPI) + `PyJWT`. В перспективе — OAuth2 через Яндекс/Google.

### Структура проекта

Доменная организация по модели Netflix Dispatch и fastapi-best-practices (24.8k ★ на GitHub):

```
resumecraft/
├── src/app/
│   ├── core/          # config, security, database, celery, storage
│   ├── auth/          # router, schemas, models, service (JWT/OAuth2)
│   ├── resumes/       # CRUD, upload, парсинг файлов
│   ├── vacancies/     # CRUD, интеграция hh.ru API
│   ├── rewriter/      # Celery tasks, оркестрация LLM
│   └── ml/            # llm_client, prompts, embeddings, resume_parser
├── streamlit_app/     # demo UI для защиты
├── tests/             # pytest + pytest-asyncio
├── alembic/           # миграции БД
└── docker-compose.yml # PostgreSQL, Redis, MinIO, Celery, Flower
```

### Схема базы данных

Гибридный подход: реляционные таблицы для сущностей + **JSONB для гибкого хранения данных резюме** (структура резюме слишком вариативна для жёсткой нормализации). Четыре основные таблицы:

- **users** — UUID PK, email, hashed_password, full_name, timestamps
- **resumes** — UUID PK, user_id FK, file_path (MinIO), `parsed_data JSONB`, raw_text, `embedding VECTOR(1536)`, status
- **vacancies** — UUID PK, user_id FK, title, description, requirements JSONB, `embedding VECTOR(1536)`, source_url
- **rewrite_history** — UUID PK, resume_id FK, vacancy_id FK, original_text, rewritten_text, model_name, tokens_used, similarity_score, user_rating

HNSW-индексы на все VECTOR-колонки для cosine similarity search.

### Деплой в России

**Docker Hub заблокирован** в России с мая 2024 — использовать Yandex Container Registry. Для MVP — VPS (Yandex Cloud / Selectel) с 4 vCPU, 8 GB RAM, 50 GB SSD. CI/CD через **GitLab CI** (доступен в России без ограничений).

## 6. Целевая аудитория: 50 млн соискателей и растущая конкуренция

### Российский рынок труда в цифрах

Россия переживает парадоксальную ситуацию: рекордно низкая безработица **2.1%** (ноябрь 2025) сочетается с **ростом конкуренции среди белых воротничков**. Вакансии для офисных работников сократились на 25% (с 777K в июне 2024 до 582K в июне 2025), в то время как число активных резюме выросло на 25%. Индекс hh.ru (число резюме на вакансию) вырос с **3.7 до 5.9–7.3** — каждая вакансия собирает в 1.5–2 раза больше откликов, чем год назад.

HeadHunter — абсолютный доминант рынка с **64.3% трафика** среди топ-20 рекрутинговых порталов. Ключевые метрики платформы:

- **93.3 млн** резюме в базе (рост с 50 млн в 2021)
- **50+ млн** уникальных соискателей
- **1.8 млн** активных вакансий ежедневно
- **1 млн+** посетителей в день
- **4.5 млн** приглашений на собеседования еженедельно
- **Выручка 2024**: 39.62 млрд ₽ (+34.5% YoY), чистая прибыль 23.88 млрд ₽ (+92.7%)

SuperJob — дистантный #2 (31 млн резюме, 8 млн посетителей/мес). Avito Работа — #3, 17 млн ежемесячных пользователей, сильна в массовом сегменте. Важная находка: **66% соискателей на SuperJob уже трудоустроены** — это работающие люди, ищущие лучшие условия, наиболее мотивированная аудитория для улучшения резюме.

### Боли соискателей — точка входа для ResumeCraft

Анализ 1000+ резюме на hh.ru (CareerLab, vc.ru) выявил системные ошибки, которые AI может исправлять автоматически:

- **Фокус на обязанностях, а не достижениях** — главная проблема российских резюме. Соискатели перечисляют должностные инструкции вместо количественных результатов
- **Размытые заголовки** — «менеджер» или «специалист» без специализации вместо точного названия целевой позиции
- **Грамматические и орфографические ошибки** — dealbreaker для большинства рекрутеров
- **Шаблонность** — ~⅓ работодателей не рассматривают типовые резюме
- **Избыточная личная информация** — хобби, семейное положение, неуместные фото
- **Незнание ATS** — **75% резюме отсеиваются** системами автоматического отбора на первом этапе

Рекрутеры тратят **6–20 секунд** на просмотр одного резюме. Российские ATS-системы (Huntflow — лидер рынка, Potok, Talantix от HH, Skillaz) активно внедряются: **44% работодателей** используют HR-системы автоматизации (2017, с тех пор значительный рост), **38% компаний** автоматизируют подбор.

### Сегменты целевой аудитории

**Молодые специалисты (приоритетный сегмент)** — 42% вакансий в 2025 году для начинающих без опыта. Самая цифрово-грамотная аудитория, максимально нуждающаяся в помощи с первым резюме. Демографический кризис 1990-х сократил эту когорту — доля резюме от соискателей до 29 лет снизилась на 7 п.п. за 5 лет.

**Mid-career профессионалы** — крупнейший активный сегмент. Работающие люди, ищущие лучшие условия. Нуждаются в обновлении устаревших резюме и перепозиционировании для новых ролей.

**IT-специалисты** — 8–9 резюме на вакансию, но острый дефицит опытных специалистов. Нуждаются в ATS-оптимизированных и англоязычных резюме для международных компаний.

### Рыночная возможность

Профессиональные услуги по написанию резюме стоят **1500–10 000₽** (Profi.ru: от 1500₽, GoodStage: 5500₽, Kwork: от 500₽). AI-сервис по цене **200–500₽** может захватить значительный объём при кратно меньшей стоимости. При конверсии **5–10%** из ~3 млн ежемесячно обновляемых резюме на hh.ru при чеке 500₽ потенциальный объём рынка — **18–36 млрд ₽/год**. Консервативная оценка: существующий рынок человеческих услуг по резюме — несколько сотен миллионов рублей ежегодно, AI-инструменты способны кратно расширить его через низкие цены и доступность.

## Заключение: ResumeCraft как первый полноценный AI-реврайтер для hh.ru

Исследование выявило три ключевых инсайта, определяющих жизнеспособность проекта. Во-первых, **структурный gap на рынке реален**: hh.ru инвестирует AI в сторону работодателей, глобальные лидеры игнорируют русский язык, а российские аналоги находятся на ранней стадии — полноценного AI-реврайтера с vacancy matching и ATS-оптимизацией для русскоязычного рынка не существует. Во-вторых, **технологический стек позволяет создать MVP с нулевым бюджетом**: FastAPI + PostgreSQL/pgvector + Celery/Redis обеспечивают продакшен-готовую архитектуру, бесплатные тиры GigaChat и Groq покрывают все потребности разработки, а PyMuPDF + python-docx + LLM-структуризация решают задачу парсинга любых форматов резюме. В-третьих, **тайминг оптимален**: рост конкуренции за вакансии (+25% активных резюме YoY при -25% вакансий) делает качество резюме критическим фактором, а 75% отсев через ATS создаёт массовый спрос на оптимизацию, о которой большинство российских соискателей даже не знает.

Для магистерского проекта ВШЭ рекомендуемый путь к MVP: FastAPI-бэкенд с Streamlit-демо, GigaChat/YandexGPT как основной LLM, интеграция с hh.ru API для извлечения требований вакансий, pipeline парсинга на PyMuPDF + python-docx, и векторный поиск через pgvector для matching резюме с вакансиями. Весь стек разворачивается в одном `docker-compose.yml` и не требует финансовых затрат на этапе разработки.

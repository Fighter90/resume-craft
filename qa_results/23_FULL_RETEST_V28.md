## ТЕСТ 2: NAV-001 — «Обновить до Pro →» (P3 LOW)

**Статус: ❌ НЕ ИСПРАВЛЕНО — STILL OPEN**

### Тестовые шаги
1. На /app/dashboard нашёл ссылку «Обновить до Pro →» в sidebar
2. Клик мышью по ссылке → НЕТ навигации
3. Исследование через DOM:
   - `elementFromPoint(90, 634)` → `<div class="plan-widget">` (НЕ ссылка)
   - Точные координаты `<a class="plan-upgrade">`: rect {top:671, left:40, width:179, height:16}
   - Клик по центру ссылки (130, 679) → `elementFromPoint` подтверждает: попадает в `<a class="plan-upgrade">`
   - Но навигации ВСЁ РАВНО нет!
4. **Исследование React internals:**
   - `__reactProps` содержит ключи: `["className","children","href","onClick","ref","target"]`
   - **hasOnClick: true** — ссылка имеет onClick обработчик

### Root Cause (обновлено)
Проблема НЕ в z-index или CSS overlay. Клик физически попадает на `<a>` элемент.

**Реальная причина:** React `onClick` обработчик на `<a>` элементе вызывает `e.preventDefault()`, что блокирует нативную навигацию по `href`. При этом onClick handler НЕ выполняет программную навигацию (через `navigate()` или `router.push()`).

### Рекомендация по исправлению

```tsx
// ВАРИАНТ 1: Убрать onClick, оставить href (если не нужна SPA-навигация)
<a href="/app/settings/subscription" className="plan-upgrade">
    Обновить до Pro →
</a>

// ВАРИАНТ 2: React Router Link (рекомендуется)
<Link to="/app/settings/subscription" className="plan-upgrade">
    Обновить до Pro →
</Link>

// ВАРИАНТ 3: Если onClick нужен для аналитики — НЕ вызывать preventDefault
<a
    href="/app/settings/subscription"
    className="plan-upgrade"
    onClick={(e) => {
        // Аналитика без preventDefault:
        trackEvent('upgrade_click');
        // НЕ вызывать e.preventDefault()!
        // Навигация произойдёт по href автоматически
    }}
>
    Обновить до Pro →
</a>
```

### Workaround
Пользователь может перейти через Настройки → Подписка.

## ТЕСТ 3: Изменение телефона — ❌ FAIL (не сохраняется)

### Шаги

1. На странице профиля ввёл телефон: `+7 (916) 123-45-67`
2. Поле с маской отобразило номер корректно
3. Нажал "Сохранить изменения"
4. `PUT /api/v1/auth/me → 200 OK`
5. Перезагрузил страницу

### Результат

**Телефон не сохранился.** После перезагрузки поле телефона вернулось к пустой маске `+7 (___) ___-__-__`.

### Баг: PROFILE-PHONE-SAVE (P2)

Номер телефона не персистится на бэкенде. Сервер возвращает 200 OK, но при следующей загрузке профиля телефон пустой. Возможные причины:
- Поле `phone` не включается в PUT-запрос (фронтенд)
- Бэкенд игнорирует поле `phone` при обновлении профиля

## ТЕСТ 6: Подтверждение email — ❌ FAIL (нет функции)

### Шаги

1. На странице профиля рядом с email отображается предупреждение: "⚠️ Не подтверждён"
2. Кликнул на предупреждение — ничего не произошло
3. Искал кнопку "Отправить повторно" / "Подтвердить email" — не найдена

### Результат

**Нет способа подтвердить email.** Предупреждение отображается, но нет кнопки для повторной отправки письма подтверждения.

### Баг: PROFILE-EMAIL-VERIFY (P3)

Отсутствует кнопка/ссылка для повторной отправки письма подтверждения email. Пользователь видит предупреждение "Не подтверждён", но не может инициировать подтверждение.

## ТЕСТ 7: Удаление фото профиля — ❌ FAIL (503 на бэкенде)

### Шаги

1. На странице профиля нажал кнопку "Удалить" рядом с аватаром
2. Аватар визуально заменён на инициалы "ТТ"

### Результат

**Визуально работает, но бэкенд ошибка:**

```
DELETE /api/v1/auth/me/avatar → 503 (Service Unavailable)
```

Фронтенд обрабатывает ошибку gracefully — удаляет аватар из UI. Но фактически на сервере аватар может остаться.

### Баг: AVATAR-DELETE-503 (P2)

Endpoint удаления аватара возвращает 503. Фронтенд маскирует ошибку — пользователь думает, что фото удалено, но сервер не обработал запрос.

## ТЕСТ 9: Удаление аккаунта — ❌ FAIL (500)

### Шаги

1. Перешёл на `/app/settings/security`
2. В разделе "Опасная зона" нажал "Удалить аккаунт"
3. Появилась форма подтверждения: поле пароля + поле "Введите УДАЛИТЬ"
4. Ввёл пароль: `TestPass1231`
5. Ввёл подтверждение: `УДАЛИТЬ`
6. Нажал "Подтвердить"

### Результат

**Ошибка:** "Внутренняя ошибка сервера" (красное сообщение в форме)

```
DELETE /api/v1/auth/me → 500 (Internal Server Error)
```

Аккаунт НЕ удалён, пользователь остаётся залогиненным.

### Баг: ACCOUNT-DELETE-500 (P1)

Удаление аккаунта полностью не работает. Endpoint `DELETE /api/v1/auth/me` возвращает 500 Internal Server Error. Это критический баг — пользователь не может удалить свой аккаунт, что может нарушать требования GDPR (право на удаление).

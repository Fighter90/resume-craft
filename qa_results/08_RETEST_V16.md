## НОВЫЕ ДЕФЕКТЫ v1.6

### NEW-001 — 🔴 CRITICAL: API-ключи в localStorage в открытом виде

**Severity:** CRITICAL
**Категория:** Безопасность
**Компонент:** Frontend / Settings / AI Models

**Описание:**
Все API-ключи LLM-провайдеров хранятся в `localStorage` браузера под ключом `ai_settings` **в открытом виде** (plaintext). Любой XSS-вектор позволяет украсть все ключи одним запросом.

**Шаги воспроизведения:**
1. Авторизоваться на resumecraft.ru
2. Открыть DevTools → Application → Local Storage
3. Найти ключ `ai_settings`
4. Прочитать JSON — все API-ключи видны

**Фактический результат:**
```json
{
  "apiKeys": {
    "gigachat": "MDU2NDkwYjUtODc1OS00NmY4LThiZGMt...",
    "openai": "sk-proj-a5W-j_XCfbhHpiUpyW9OUF3Ob1CB-...",
    "anthropic": "sk-ant-api03-Oge6dlQADqxoxI2bISph...",
    "openrouter": "sk-or-v1-42b0e8f8bcbf609ce9b493..."
  }
}
```

**Ожидаемый результат:**
API-ключи должны храниться ТОЛЬКО на сервере. Фронтенд не должен иметь доступа к ключам после их первоначальной отправки.

**Влияние:**
- Любой XSS крадёт все API-ключи пользователя
- Ключи доступны всем browser extensions
- Ключи не очищаются при logout
- Финансовые потери пользователей (использование их API-квот)

**Рекомендация:**
Хранить ключи серверно. На фронт отдавать только маску (последние 4 символа).

### NEW-002 — 🟠 HIGH: Рассинхрон UI и бэкенда по API-ключам

**Severity:** HIGH
**Категория:** Бизнес-логика
**Компонент:** Settings → AI-модели + Backend

**Описание:**
В настройках AI-модели все 4 провайдера показывают замаскированные ключи (●●●●●), а ⚠️ предупреждения рядом с названиями. При попытке оптимизации бэкенд возвращает "API-ключ не настроен". Налицо рассинхрон: фронтенд считает ключи сохранёнными, бэкенд — нет.

**Шаги воспроизведения:**
1. Перейти в Настройки → AI-модели
2. Видно: GigaChat Pro ⚠️, OpenAI ⚠️, Anthropic Claude ⚠️, OpenRouter ⚠️
3. Прокрутить до "API-ключи" — все 4 поля заполнены (●●●●●)
4. Запустить оптимизацию → "API-ключ не настроен"

**Фактический результат:**
UI показывает ключи как настроенные (маскированные), но бэкенд не может их использовать.

**Ожидаемый результат:**
Если ключи не валидны/не настроены — UI должен показывать пустые поля или сообщение "Ключ не настроен".

### NEW-003 — 🟡 MEDIUM: Нет верификации email при регистрации

**Severity:** MEDIUM
**Категория:** Безопасность / Бизнес-логика
**Компонент:** Auth / Registration

**Описание:**
При регистрации нового пользователя email не верифицируется. Аккаунт создаётся мгновенно с access_token. В профиле email отображается как "Подтверждён" без фактического подтверждения.

**Шаги воспроизведения:**
```
POST /api/v1/auth/register
{"email": "any_email_123@example.com", "password": "TestPass123", "full_name": "Test"}
```

**Фактический результат:**
HTTP 201, аккаунт создан, токен выдан. Статус email: "Подтверждён".

**Ожидаемый результат:**
Email-верификация перед активацией аккаунта.

**Влияние:**
- Спам-регистрации
- Регистрация на чужие email-адреса
- Нет механизма восстановления пароля

### NEW-004 — 🟡 MEDIUM: Аватар другого пользователя в localStorage

**Severity:** MEDIUM
**Категория:** Утечка данных
**Компонент:** Frontend / User Profile

**Описание:**
В localStorage текущего пользователя (`1f4367a9-...`) хранится аватар другого пользователя (`user_avatar_80cb1eb7-...`, 134 KB). Это утечка данных между сессиями/пользователями.

**Шаги воспроизведения:**
1. Авторизоваться как test_new@example.com
2. DevTools → Application → Local Storage
3. Найти ключ `user_avatar_80cb1eb7-d565-4a53-a71e-8d8d277fe28d`

**Фактический результат:**
Аватар другого пользователя (134 739 символов base64) доступен.

**Ожидаемый результат:**
localStorage должен содержать данные только текущего пользователя. При логауте — полная очистка.

### NEW-005 — 🟡 MEDIUM: DELETE резюме без подтверждения через API

**Severity:** MEDIUM
**Категория:** Безопасность / API
**Компонент:** Backend / Resumes API

**Описание:**
Эндпоинт `DELETE /api/v1/resumes/{id}` удаляет резюме мгновенно без дополнительного подтверждения. Нет soft-delete, нет корзины, нет возможности восстановления.

**Шаги воспроизведения:**
```
DELETE /api/v1/resumes/c4647c8a-df7c-47c1-9f13-2c671bae7767
Authorization: Bearer <token>
```

**Фактический результат:**
HTTP 204 No Content. Резюме удалено безвозвратно.

**Ожидаемый результат:**
Soft-delete с возможностью восстановления в течение 30 дней, или подтверждение через API (двухэтапное удаление).

### NEW-006 — 🟢 LOW: Нет rate limiting на API-эндпоинтах

**Severity:** LOW (дубликат LIVE-012, расширенный скоуп)

**Описание:**

**Тестовые данные:**
```javascript
// 10 параллельных запросов
Promise.all(Array(10).fill(0).map(() =>
  fetch('/api/v1/auth/me', {headers: {'Authorization': `Bearer ${token}`}})
))
// Результат: все 200, 583ms
```

## Заключение

**Основная функция сервиса (AI-оптимизация резюме) по-прежнему не работает.** Несмотря на то что LIVE-002 был помечен как FIXED, все LLM-провайдеры возвращают ошибку "API-ключ не настроен".

Обнаружена новая критическая уязвимость: API-ключи всех LLM-провайдеров хранятся в localStorage браузера в открытом виде (NEW-001).

Из позитивного — 6 багов из 16 действительно исправлены, включая критические (Swagger UI, счётчик оптимизаций, health-check).

## 🔵 FEATURE-001 — Экспорт резюме: добавить формат TXT

**Приоритет:** HIGH
**Затрагивает:** Frontend + Backend

### Описание
На странице экспорта `/app/export/{rewrite_id}` добавить четвёртый формат — **TXT (Plain Text)**. Пользователь должен иметь возможность скачать оптимизированное резюме в виде чистого текста без форматирования.

### Текущее состояние
Страница экспорта уже содержит 3 карточки: DOCX, PDF, hh.ru. Нужно добавить TXT.

### Требования к UI

**Карточка TXT:**
```
┌─────────────────────┐
│        📄           │
│        TXT          │
│  Простой текст —    │
│  универсальный      │
│  формат             │
└─────────────────────┘
```

- Расположение: **четвёртая карточка** в ряду (после hh.ru), либо **третья** (между PDF и hh.ru) — на выбор дизайнера
- Иконка: текстовый документ (отличная от DOCX/PDF)
- Подпись: `TXT` + описание `Простой текст — универсальный формат`
- При выборе: кнопка меняется на **«Скачать TXT»**
- Файл: `resume_optimized.txt`
- Шаблон оформления: **скрывать секцию «Шаблон оформления»** при выборе TXT (в plain text нет форматирования)

### Требования к Backend

**Новый API endpoint:**
```
GET /api/v1/export/{rewrite_id}/txt
Response: Content-Type: text/plain; charset=utf-8
Content-Disposition: attachment; filename="resume_optimized.txt"
```

**Алгоритм генерации TXT:**
1. Получить оптимизированный текст из `rewrite_result.optimized_text`
2. Если `optimized_text` содержит JSON — распарсить и извлечь секции
3. Сформировать plain text с базовым форматированием:
   - Разделители секций: `===` или `---`
   - Заголовки секций: ЗАГЛАВНЫМИ БУКВАМИ
   - Списки достижений: `• ` или `- ` (маркеры)
   - Пустые строки между секциями
4. Кодировка: **UTF-8 с BOM** (для корректного открытия в Windows Notepad)

**Пример выходного TXT файла:**

## 🔵 FEATURE-002 — Кнопка «Скачать» на странице «Мои резюме»: выбор формата

**Приоритет:** HIGH
**Затрагивает:** Frontend

### Описание
На странице `/app/resumes` кнопка ⬇ (Скачать) сейчас скачивает ТОЛЬКО DOCX без выбора. Необходимо добавить **dropdown-меню выбора формата** при клике на кнопку скачивания.

### Текущее поведение
```
Клик на ⬇ → GET /api/v1/export/{rewrite_id}/docx → скачивание DOCX
```

### Требуемое поведение
```
Клик на ⬇ → Dropdown:
  ┌──────────────────┐
  │ 📄 Скачать DOCX  │
  │ 📑 Скачать PDF   │
  │ 📝 Скачать TXT   │
  └──────────────────┘
→ Клик на формат → GET /api/v1/export/{rewrite_id}/{format} → скачивание
```

### Требования к UI
1. При клике на кнопку ⬇ — открывать **popup/dropdown меню**
2. Пункты меню:
   - `📄 Скачать DOCX` — вызов `/api/v1/export/{id}/docx`
   - `📑 Скачать PDF` — вызов `/api/v1/export/{id}/pdf`
   - `📝 Скачать TXT` — вызов `/api/v1/export/{id}/txt`
3. Если у резюме нет оптимизированной версии (статус ≠ «Оптимизировано»):
   - Показать: `📥 Скачать оригинал` — вызов `/api/v1/resumes/{id}/file`
4. Закрытие dropdown: клик вне меню или по Escape
5. Анимация: плавное появление (fade + slide down, 150ms)

### Важные нюансы
- Для резюме со статусом «Оптимизировано» — скачивать **оптимизированный** вариант
- Для резюме со статусом «Загружено» / «В обработке» — скачивать только **оригинал**
- Нужен `rewrite_id` для экспорта оптимизированной версии (его можно получить через API связи resume → rewrite)

### Структура контента в просмотрщике

**Три таба:**

**Таб 1: Оригинал**
- Показывает загруженный пользователем текст резюме
- Источник данных: `GET /api/v1/resumes/{id}` → поле `parsed_text` или `original_text`
- Форматирование: plain text с разбивкой на параграфы

**Таб 2: Оптимизировано** (активен по умолчанию, если есть оптимизация)
- Показывает оптимизированный текст с полным форматированием
- Источник данных: `GET /api/v1/rewrite/{rewrite_id}/result` → поле `optimized_text`
- Если `optimized_text` — JSON строка, **распарсить и отрендерить**:

```typescript
interface OptimizedResume {
  summary: string;           // Профессиональное резюме
  experience: {
    position: string;        // Должность
    company: string;         // Компания
    period: string;          // Период работы
    achievements: string[];  // Список достижений
  }[];
  education: {
    institution: string;     // Учебное заведение
    degree: string;          // Специальность
    period: string;          // Годы обучения
  }[];
  skills: string[];          // Навыки
  contacts: {
    name: string;            // ФИО
    phone?: string;          // Телефон
    email?: string;          // Email
    city?: string;           // Город
  };
}
```

**Алгоритм рендеринга форматированного текста:**
1. Получить `optimized_text` из API
2. Проверить: начинается ли с `{` или `"json {` (JSON формат)
   - **Да** → распарсить JSON, извлечь секции, отрендерить по шаблону
   - **Нет** → обработать как Markdown/plain text
3. Рендеринг секций:
   - **Контакты** → Блок с именем крупным шрифтом, контакты в строку
   - **Резюме/Summary** → Параграф с выделением ключевых слов
   - **Опыт** → Карточки с заголовком (должность + компания), период, bullet-list достижений
   - **Образование** → Таблица или карточки
   - **Навыки** → Теги/badges в строку
4. CSS-стили:
   - Шрифт: системный sans-serif, 14-16px
   - Заголовки секций: 18px, bold, с иконками
   - Разделители между секциями
   - Адаптивная ширина (max-width: 800px, по центру)

**Таб 3: Сравнение**
- Side-by-side оригинал vs оптимизированный
- Подсветка изменений (зелёный = добавлено, красный = удалено)
- Аналог diff-view
- Источник: данные с результатов (уже есть на странице `/app/results`)

## 🔵 FEATURE-005 — Вьюер DOCX для загруженных файлов

**Приоритет:** MEDIUM
**Затрагивает:** Frontend

### Описание
Если пользователь загрузил резюме в формате **DOCX**, при просмотре нужен **встроенный вьюер** для DOCX файлов.

### Проблема
Браузеры не умеют нативно отображать DOCX. Нужна конвертация на frontend или backend.

### Варианты реализации

**Вариант A — Конвертация DOCX → HTML на Backend (рекомендуемый):**
```
GET /api/v1/resumes/{id}/preview/html
Response: Content-Type: text/html
Body: <html>...отрендеренный из DOCX документ...</html>
```
- Библиотека: `python-docx` → `mammoth` (Python) или `libreoffice --headless --convert-to html`
- Преимущества: точный рендеринг, поддержка стилей, таблиц, изображений
- Рендерить в `<iframe>` или `dangerouslySetInnerHTML` (с sanitize)

**Вариант B — Конвертация DOCX → HTML на Frontend:**
```bash
npm install mammoth
```
```typescript
import mammoth from 'mammoth';

const result = await mammoth.convertToHtml({ arrayBuffer: docxBuffer });
const html = result.value; // HTML строка
```
- Получить DOCX бинарный файл через `GET /api/v1/resumes/{id}/file`
- Сконвертировать на клиенте через mammoth.js
- Отобразить HTML

**Вариант C — Конвертация DOCX → PDF на Backend:**
- Сконвертировать DOCX в PDF через LibreOffice
- Показать через PDF-вьюер (FEATURE-004)
- Универсально, но теряет редактируемость

1. **HTML рендеринг** — стили, таблицы, списки, заголовки

3. **Скачивание** — кнопка скачать оригинальный DOCX
4. **Масштабирование** — зум контента (CSS transform)
5. **Печать** — кнопка `Ctrl+P` / Print

## 🔧 Общая архитектура просмотрщика

### Логика кнопки 👁 (Просмотр)

```typescript
// Алгоритм при клике на кнопку просмотра
async function handleViewResume(resume: Resume) {
  // 1. Если есть оптимизированная версия → открыть просмотрщик с форматированием
  if (resume.status === 'optimized' && resume.latest_rewrite_id) {
    openResumeViewer({
      mode: 'optimized',
      resumeId: resume.id,
      rewriteId: resume.latest_rewrite_id,
      tabs: ['original', 'optimized', 'comparison']
    });
    return;
  }

  // 2. Если загружен PDF → открыть PDF вьюер
  if (resume.format === 'pdf') {
    openPdfViewer({
      fileUrl: `/api/v1/resumes/${resume.id}/file`,
      parsedText: resume.parsed_text,
      tabs: ['pdf', 'text']
    });
    return;
  }

  // 3. Если загружен DOCX → открыть DOCX вьюер
  if (resume.format === 'docx') {
    openDocxViewer({
      fileUrl: `/api/v1/resumes/${resume.id}/file`,
      parsedText: resume.parsed_text,
      tabs: ['document', 'text']
    });
    return;
  }

  // 4. Fallback → показать plain text
  openTextViewer({
    text: resume.parsed_text
  });
}
```

### Клик по названию резюме
Клик по названию в таблице **должен работать так же**, как клик на 👁 — открывать просмотрщик.

```tsx
<td onClick={() => handleViewResume(resume)} style={{ cursor: 'pointer' }}>
  {resume.name}
</td>
```

## 🔴 АКТИВНЫЕ ДЕФЕКТЫ — ТРЕБУЮТ ИСПРАВЛЕНИЯ

### ДЕФЕКТ 1 — SECURITY-AUTOFILL (P4): Автозаполнение пароля

**Проблема:**
На странице `/app/settings/security` поля "Текущий пароль" и "Подтвердите пароль" автозаполняются браузером. Это создаёт UX-проблему — пользователь видит якобы заполненные поля.

**Решение:**
Добавить атрибуты к полям паролей:
```html
<input type="password" autocomplete="new-password" />
```

Для поля текущего пароля:
```html
<input type="password" autocomplete="current-password" />
```

**Серьёзность:** P4 — косметическая проблема, не влияет на безопасность напрямую.

### ДЕФЕКТ 2 — GROQ-MODEL-NAME-HISTORY (P4): Groq без названия модели

**Проблема:**
На странице `/app/history` запись об оптимизации Groq отображается как "Оптимизация · Groq" без указания конкретной модели. Все остальные провайдеры отображают полное название: "Провайдер · Модель".

| Провайдер | Фактическое | Ожидаемое |
|-----------|-------------|-----------|
| GigaChat | ✅ GigaChat · GigaChat-Pro | GigaChat · GigaChat-Pro |
| OpenAI | ✅ OpenAI · o4-mini-2025-04-16 | OpenAI · o4-mini-2025-04-16 |
| Anthropic | ✅ Anthropic · claude-sonnet-4-6 | Anthropic · claude-sonnet-4-6 |
| OpenRouter | ✅ OpenRouter · ai21/jamba-large-1.7 | OpenRouter · ai21/jamba-large-1.7 |
| Groq | ❌ Groq | Groq · allam-2-7b |

**Решение:**
В backend-коде при сохранении результата оптимизации для Groq нужно сохранять полное имя модели (включая конкретную модель, напр. "allam-2-7b"), а не просто название провайдера.

Проверить:
1. API response от Groq — содержит ли `model` field
2. Маппинг в коде сохранения результата — возможно, для Groq модель не парсится из ответа

**Серьёзность:** P4 — косметический баг.

### ДЕФЕКТ 3 — AVATAR-DELETE-503 (P2): Удаление аватара → 503

**Проблема:**
На странице `/app/settings/profile` при удалении загруженного аватара сервер возвращает 503 Service Unavailable. UI не показывает ошибку пользователю (silent failure).

**Шаги воспроизведения:**
1. Перейти на `/app/settings/profile`
2. Загрузить аватар (POST /api/v1/auth/me/avatar → 200 OK)
3. Нажать "Удалить"
4. `DELETE /api/v1/auth/me/avatar → 503 Service Unavailable`

**Дополнительно:**
- Кнопка "Удалить" видна даже без загруженного аватара (UX-баг AVATAR-DELETE-BTN-UX)
- UI не показывает ошибку при 503 — silent failure

**Решение:**
1. Исправить endpoint `DELETE /api/v1/auth/me/avatar` (503 → 200/204)
2. Добавить обработку ошибок в UI (показать toast при неудачном удалении)
3. Скрыть кнопку "Удалить" когда аватар не загружен

**Серьёзность:** P2 — backend ошибка с невозможностью выполнить действие.

### ДЕФЕКТ 4 — VACANCY-URL-500 (P3): Невалидный URL вакансии → 500

**Проблема:**
На странице `/app/vacancy`, вкладка "Вставить URL" — при вводе невалидной ссылки (не hh.ru) сервер возвращает 500 Internal Server Error вместо корректного сообщения об ошибке.

**Шаги воспроизведения:**
1. Перейти на `/app/vacancy`
2. Выбрать вкладку "Вставить URL"
3. Ввести `https://google.com/not-hh`
4. Нажать "Загрузить"
5. `POST /api/v1/vacancies/from-url → 500 Internal Server Error`

**Ожидаемое:** 400 Bad Request с сообщением валидации.

**Решение:**
Добавить серверную валидацию URL до попытки парсинга:
- Проверить что URL содержит `hh.ru/vacancy/`
- Если нет — вернуть 400 с понятным сообщением

**Серьёзность:** P3 — серверная ошибка, отсутствие входной валидации.

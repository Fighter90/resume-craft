## Контекст

Ты — опытный full-stack разработчик. Тебе поставлена задача: исправить все баги в проекте **ResumeCraft** — SaaS-сервис для оптимизации резюме под вакансии с помощью AI (LLM).

## Полный список багов для исправления (23 дефекта)

### 🔴 CRITICAL — Фаза 0 (исправить НЕМЕДЛЕННО)

#### 1. NEW-008: DELETE аккаунта без подтверждения → FIX-009
`DELETE /api/v1/auth/me` мгновенно каскадно удаляет аккаунт и ВСЕ данные (резюме, историю, настройки) без подтверждения пароля. Нет soft-delete.

**Что делать:**
- Требовать пароль в теле запроса: `{"password": "..."}`
- Реализовать soft-delete: поле `deleted_at` + `scheduled_deletion` (30 дней)
- Уведомление на email
- Celery/cron-задача для окончательного удаления
- Фронт: модалка подтверждения с вводом пароля

#### 2. LIVE-002: Все LLM-провайдеры `available: false` → FIX-002
Основная функция — оптимизация резюме — НЕ РАБОТАЕТ. Все 4 модели: `available: false`, сообщение "API-ключ не настроен".

**Что делать:**
- Бэкенд: при оптимизации брать API-ключи из БД (после FIX-001)
- Проверять наличие ключа ДО начала обработки
- Wizard: показывать только модели с настроенными ключами

#### 3. NEW-001: API-ключи в localStorage в plaintext → FIX-001
В `localStorage` под ключом `ai_settings` хранятся 4 API-ключа LLM-провайдеров в открытом виде. Там же: аватар чужого пользователя, настройки моделей.

**Что делать:**
- Создать таблицу `user_settings` в БД
- Шифрование API-ключей через `cryptography.fernet`
- API: `GET /settings/ai-keys` возвращает ТОЛЬКО маски (`●●●●●xyz`)
- API: `PUT /settings/ai-keys/{provider}` сохраняет зашифрованно
- Фронт: убрать ВСЕ обращения к localStorage для настроек AI
- При logout — `localStorage.clear()`

### 🟠 HIGH — Фаза 1 (1-2 дня)

#### 4. NEW-010: Кнопка "Найти" в wizard disabled → FIX-010
На странице поиска вакансий кнопка "Найти" имеет `disabled: true` даже при заполненных полях. Wizard нерабочий.

**Что делать:**

#### 5. NEW-009: Кнопка просмотра резюме (👁) не работает → FIX-011
Клик по иконке глаза на странице "Мои резюме" — нет реакции, нет сетевых запросов, нет навигации.

**Что делать:**
- Проверить onClick binding на кнопке (не на вложенном SVG)
- Проверить event propagation (stopPropagation)
- Проверить роутинг для `/app/resumes/:id`

#### 6. NEW-002: Рассинхрон UI/бэкенд по API-ключам
Фронт показывает "ключ настроен" (маска), но бэкенд говорит "ключ не настроен". Причина: ключи в localStorage, бэкенд о них не знает.

**Что делать:** Решается через FIX-001 (перенос ключей в БД)

#### 7. LIVE-012: Нет rate limiting → FIX-005
10 неудачных логинов подряд — все 401, ни одного 429. Нет защиты ни на одном эндпоинте.

**Что делать:**
- Установить `slowapi`
- Логин: 5/минуту, Регистрация: 3/минуту, Оптимизация: 10/час
- Глобальный лимит: 100/минуту
- Возвращать `Retry-After` header

#### 8. NEW-014: Экспорт PDF и TXT не реализован → FIX-003
Из 3 форматов экспорта (PDF, DOCX, TXT) реализован ТОЛЬКО DOCX. PDF и TXT — 404.

**Что делать:**
- `reportlab` для генерации PDF
- Plain text для TXT
- Backend: `GET /api/v1/export/{task_id}/{format}` для pdf, docx, txt
- Frontend: 3 кнопки экспорта на странице резюме

#### 9. SEC-001: Реальные API-ключи в .env (operational)
Проверить что в production `.env` нет захардкоженных ключей, используются переменные окружения.

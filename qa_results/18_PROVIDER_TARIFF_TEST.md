### Тест 1: Переключение Free → Pro (test@example.com)

**Действие:** Нажал "Повысить" на карточке Pro
**Ожидание:** Редирект на страницу оплаты Robokassa → после оплаты план меняется
**Результат:** ❌ **КРИТИЧЕСКИЙ БАГ**

1. План мгновенно переключился на "Pro" **без оплаты**
2. Страница подписки показывает "Pro" с "5 из ∞"
3. **НО:** Сайдбар продолжает показывать "Бесплатный план"
4. При попытке оптимизации: **"Лимит оптимизаций исчерпан"** — бэкенд всё ещё считает план бесплатным

**Вывод:** Переключение тарифа — это **ТОЛЬКО фронтенд-стейт**, не сохраняется в бэкенде.

## ЧАСТЬ 4: РЕКОМЕНДАЦИИ

### Приоритет 1 — Тарифная система (TARIFF-001, TARIFF-002)

1. **Интегрировать Robokassa:** Кнопка "Повысить" должна перенаправлять на страницу оплаты, а не менять стейт фронтенда
2. **Backend API:** Создать эндпоинт `POST /api/subscription/upgrade` который:
   - Инициирует платёж через Robokassa
   - По callback Robokassa обновляет план в БД
   - Возвращает обновлённый статус подписки
3. **Альтернатива (для тестирования):** Если оплата ещё не готова, убрать кнопки "Повысить" или показывать "Скоро" / "В разработке"

### Приоритет 2 — Сайдбар (SIDEBAR-001, SIDEBAR-002)

1. Сайдбар должен получать данные из API (не из локального стейта)
2. После успешной оптимизации — refetch данных пользователя
3. Показывать актуальный план и счётчик

### Приоритет 3 — Лимит (LIMIT-001)

1. Проверять лимит на первом шаге (Upload), показывая баннер "Лимит исчерпан. Обновите план."
2. Или блокировать кнопку "+ Оптимизировать резюме" на дашборде при достижении лимита

### Приоритет 4 — Провайдеры (GIGACHAT-001, GROQ-001)

1. Проверить и обновить API-ключ GigaChat
2. Добавить Groq в список провайдеров (или убрать из конфигурации если не планируется)
3. Улучшить сообщения об ошибках провайдеров — показывать конкретную причину

### Приоритет 5 — Результаты (ATS-001, SCORE-001)

1. Исправить маппинг ATS Grade → лейбл (A=Отлично, B=Хорошо, C=Средне, D=Плохо)
2. Пересмотреть формулу Match Score — компоненты не должны быть идентичными

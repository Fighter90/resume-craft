## FIX-V17-001 — 🔴 CRITICAL: Кнопка «Найти» не вызывает API

**Файл:** Фронтенд, компонент поиска вакансий (предположительно `VacancySearch.tsx` или `SearchTab.tsx`)

**Проблема:** Кнопка «Найти» на вкладке «Поиск на hh.ru» (страница `/app/vacancy?resumeId=...`) при клике ничего не делает. onClick handler не отправляет HTTP-запрос.

**Бэкенд работает корректно:**
```
GET /api/v1/vacancies/search?text=Product+Manager&area=1 → 200 OK
```
Возвращает массив вакансий с hh.ru (hh_id, title, company, salary, url).

**Что проверить:**
1. Обработчик onClick на кнопке «Найти» — возможно не привязан или привязан к пустой функции
2. Параметры запроса: endpoint использует `text` (не `query`) и `area` (не `city`)
3. Ранее `GET /api/v1/vacancies/search?query=...` возвращал 422 — возможно фронтенд отправляет `query` вместо `text`

**Критерий приёмки:**
- Ввести запрос + город → нажать «Найти» → отобразить список вакансий
- Клик на вакансию → выбор → переход к выбору модели

## FIX-V17-003 — 🟠 HIGH: Match Score 1% вместо реальных значений

**Файл:** Фронтенд, компонент отображения Score (предположительно `MatchScore.tsx`, `ScoreCard.tsx`)

**Проблема:** API возвращает десятичные значения:
```json
{
  "match_score_before": 0.601,
  "match_score_after": 0.773
}
```
UI отображает «1%» для всех значений.

**Варианты причин:**
1. Фронтенд не умножает значение на 100 (0.773 → отображает как 0.77 → округляет до 1)
2. Фронтенд ищет поле с другим именем (например `match_score` вместо `match_score_after`)
3. Компоненты скоринга (Keywords, Experience, Structure, Readability) не передаются из бэкенда

**Фикс:**
1. Убедиться что `Math.round(match_score_after * 100)` = 77
2. Вычислять дельту: `Math.round((match_score_after - match_score_before) * 100)` = 17
3. Передавать компоненты скоринга из бэкенда (или вычислять на фронтенде по формуле: Keywords 40% + Experience 25% + Structure 20% + Readability 15%)

**Критерий приёмки:**
- Match Score показывает 77% (не 1%)
- Улучшение показывает «+17 пунктов»
- Компоненты показывают индивидуальные значения

## FIX-V17-004 — 🟠 HIGH: OpenAI o4-mini ошибка max_tokens

**Файл:** Бэкенд, модуль LLM-провайдеров (предположительно `llm_service.py` или `openai_provider.py`)

**Проблема:** При вызове моделей серии `o*` (o1, o3, o4-mini) OpenAI API возвращает:
```
Error code: 400 - Unsupported parameter: 'max_tokens' is not supported
with this model. Use 'max_completion_tokens' instead.
```

**Фикс:**
```python
# При формировании запроса к OpenAI:
if model.startswith(('o1', 'o3', 'o4')):
    params['max_completion_tokens'] = params.pop('max_tokens', 4096)
else:
    # оставить max_tokens для gpt-* моделей
    pass
```

**Критерий приёмки:**
- Оптимизация через `openai:o4-mini` завершается успешно
- Оптимизация через `openai:gpt-4o` тоже работает (не сломать)

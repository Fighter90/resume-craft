## ДЕФЕКТ 1 (P0): Смена тарифа без оплаты — TARIFF-001

**Проблема:** Кнопка "Повысить" на `/app/subscription` мгновенно меняет план в UI без вызова API оплаты (Robokassa). Это чисто фронтенд-стейт, бэкенд не знает о смене.

**Текущее поведение:**
```
Пользователь нажимает "Повысить" → useState меняет plan на "pro" → UI показывает "Pro"
→ Никакого API вызова → Бэкенд считает план "free"
```

**Ожидаемое поведение:**
```
Пользователь нажимает "Повысить" → Редирект на Robokassa → Оплата
→ Robokassa callback → Backend обновляет plan в БД → UI обновляется
```

**Как исправить:**

### Вариант А: Полная интеграция Robokassa
1. Backend: создать `POST /api/subscription/create-payment` → генерирует ссылку Robokassa
2. Frontend: кнопка "Повысить" вызывает этот эндпоинт → redirect на Robokassa
3. Backend: webhook `POST /api/subscription/robokassa-callback` → обновляет plan в users table
4. Frontend: после возврата с Robokassa — refetch user data

### Вариант Б: Временная заглушка (если оплата не готова)
1. Заменить кнопку "Повысить" на "Скоро" (disabled) или убрать карточки платных планов
2. Показывать текст: "Платные тарифы будут доступны в ближайшее время"

**Как исправить:**

2. Добавить health-check для каждого провайдера при старте сервера
3. Если провайдер недоступен — помечать его в UI как "Недоступен" с причиной

## ДЕФЕКТ 6 (P2): Неинформативное сообщение об ошибке провайдера — GIGACHAT-002

**Проблема:** Сообщение "Ошибка тарификации у поставщика модели" не говорит пользователю конкретную причину.

**Как исправить:**
```python
# В обработчике ошибок провайдера:
except ProviderBillingError as e:
    # Вместо общего сообщения — конкретика:
    if "authentication" in str(e).lower():
        error_msg = "Ошибка аутентификации провайдера. Обратитесь в поддержку."
    elif "balance" in str(e).lower() or "quota" in str(e).lower():
        error_msg = "Недостаточно средств на аккаунте провайдера. Попробуйте другую модель."
    elif "rate_limit" in str(e).lower():
        error_msg = "Превышен лимит запросов. Попробуйте через минуту."
    else:
        error_msg = f"Ошибка провайдера: {e.provider_message}. Попробуйте другую модель."
```

## ДЕФЕКТ 8 (P2): Все компоненты Match Score идентичны — SCORE-001

**Проблема:** Все 4 компонента Match Score показывают одинаковый процент (43%). При разных весах (40/25/20/15%) и разных метриках это крайне маловероятно.

**Как исправить:**
```
Проверить backend endpoint, который рассчитывает скор.
Вероятная ошибка: вместо 4 разных значений, один общий скор копируется во все поля.

Ожидаемое:
- Ключевые слова: рассчитывается по keyword overlap
- Опыт: рассчитывается по matching experience
- Структура: рассчитывается по секциям резюме
- Читаемость: рассчитывается по длине предложений, grammar

Каждый компонент должен иметь независимый score.
```

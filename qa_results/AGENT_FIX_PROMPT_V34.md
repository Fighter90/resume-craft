## 🔴 Замечание 1 (P2): HH-RESUME-LINK-405 — Загрузка резюме по ссылке hh.ru не работает (405)

### Описание проблемы

На странице `/app/upload` (вкладка "Ссылка hh.ru") при вводе ссылки на резюме hh.ru и нажатии "Загрузить резюме" сервер возвращает **405 (Method Not Allowed)** на `POST /api/v1/resumes/from-url`. Endpoint существует, но метод POST не реализован.

Фронтенд корректно обрабатывает ошибку и показывает пользователю сообщение: *"Не удалось автоматически загрузить резюме с hh.ru. Скопируйте текст резюме вручную на вкладке «Вставить текст»."* — это хороший UX fallback, но сама функция не работает.

### Воспроизведение

```
1. Войти в аккаунт
2. Перейти на /app/upload → вкладка "Ссылка hh.ru"
3. Ввести ссылку: https://hh.ru/resume/90d67b47ff01c53bfd0039ed1f36424d765046
4. Нажать "Загрузить резюме"
5. РЕЗУЛЬТАТ: Ошибка "Не удалось автоматически загрузить резюме с hh.ru"
6. ОЖИДАНИЕ: Парсинг резюме по ссылке → переход на страницу вакансии
```

### Технические детали

```
Network:
POST /api/v1/resumes/from-url → 405 (Method Not Allowed)
POST /api/v1/resumes/from-text → 422 (Unprocessable Entity, fallback attempt)
```

### Рекомендации по исправлению

**Вариант А (реализовать серверный парсинг hh.ru):**

```python
@router.post("/api/v1/resumes/from-url")
async def import_resume_from_url(url: str, user: User = Depends(get_current_user)):
    # 1. Валидация URL
    if not re.match(r'^https?://(www\.)?hh\.ru/resume/[a-f0-9]+', url):
        raise HTTPException(400, "Поддерживаются только ссылки на резюме hh.ru")

    # 2. Попытка парсинга (hh.ru может требовать авторизацию)
    try:
        text = await fetch_and_parse_hh_resume(url)
        if not text or len(text.strip()) < 50:
            raise HTTPException(400, "Не удалось извлечь текст. Резюме может быть скрыто настройками приватности.")
        return {"text": text, "source": "hh_url"}
    except HHAccessDenied:
        raise HTTPException(403, "Резюме закрыто настройками приватности на hh.ru. Скопируйте текст вручную.")
    except Exception as e:
        logger.error(f"hh.ru parse error: {e}")
        raise HTTPException(400, "Не удалось загрузить резюме. Скопируйте текст вручную.")
```

**Вариант Б (убрать вкладку, если не реализовано):**

Если серверный парсинг hh.ru не планируется (hh.ru блокирует скрейпинг, требует авторизацию), лучше временно скрыть вкладку "Ссылка hh.ru", чтобы не вводить пользователей в заблуждение. Оставить "Вставить текст" и "Загрузить файл".

**Вариант В (client-side redirect):**

Вместо вызова API показать пользователю инструкцию: "Откройте ссылку, скопируйте текст резюме и вставьте на вкладке «Вставить текст»". Это честно и не создаёт ожиданий автоматического импорта.

### Тест-кейс

```
1. Ввести валидную ссылку hh.ru/resume/... → нажать "Загрузить"
2. ОЖИДАНИЕ: Текст резюме извлечён (или понятная ошибка, если hh.ru блокирует)
3. Ввести невалидную ссылку (google.com) → нажать "Загрузить"
4. ОЖИДАНИЕ: Ошибка "Поддерживаются только ссылки hh.ru"
5. Оставить поле пустым → нажать "Загрузить"
6. ОЖИДАНИЕ: Ошибка "Введите ссылку на резюме"
```

## 🟡 Замечание 2 (P2): PDF-PARSE-502 — "Bad Gateway" при загрузке PDF-файла

### Описание проблемы

При загрузке PDF-файла через форму "Загрузить файл" сервер возвращает ошибку **"Bad Gateway" (502)** вместо человекопонятного сообщения. Файл принимается фронтендом (показывается имя и размер), но бэкенд не может обработать файл.

**Уточнение (Report #31):** Маленький well-formed PDF (2.4 КБ, создан reportlab) **парсится успешно**. Ошибка 502 воспроизводится на PDF-файлах большего размера или определённой структуры. Необходимо дополнительное тестирование с реальными PDF-резюме (> 100 КБ).

### Воспроизведение

```
1. Зарегистрировать/войти в аккаунт
2. Перейти на /app/upload → вкладка "Загрузить файл"
3. Загрузить PDF-файл (реальное резюме > 100 КБ)
4. Нажать "Продолжить"
5. РЕЗУЛЬТАТ: Красная ошибка "Bad Gateway" под кнопкой
6. ОЖИДАНИЕ: Парсинг PDF → переход на страницу вакансии
```

### Рекомендации по исправлению

**1. Обернуть парсинг PDF в try/except:**

```python
# В endpoint загрузки резюме:
@router.post("/api/v1/resumes/upload")
async def upload_resume(file: UploadFile):
    try:
        if file.content_type == "application/pdf":
            text = extract_text_from_pdf(file)  # PyMuPDF
        elif file.content_type == "application/vnd.openxmlformats-officedocument.wordprocessingml.document":
            text = extract_text_from_docx(file)  # python-docx
        else:
            raise HTTPException(400, "Неподдерживаемый формат файла")

        if not text or len(text.strip()) < 50:
            raise HTTPException(400, "Не удалось извлечь текст из файла. Убедитесь, что файл содержит текстовый слой.")

        return {"text": text, "source": "file"}

    except HTTPException:
        raise
    except Exception as e:
        logger.error(f"PDF parse error: {e}")
        raise HTTPException(400, "Ошибка при обработке файла. Попробуйте другой файл или вставьте текст вручную.")
```

**2. Проверить лимит размера файла на nginx/reverse proxy:**

502 Bad Gateway часто возникает из-за таймаута reverse proxy при обработке больших файлов. Проверить:

```nginx
# nginx.conf
client_max_body_size 10M;
proxy_read_timeout 30s;
proxy_send_timeout 30s;
```

**3. Добавить валидацию на фронтенде:**

```typescript
// Проверить минимальный размер файла перед отправкой:
if (file.size < 100) {
  showError('Файл слишком маленький. Загрузите полноценное резюме.');
  return;
}
if (file.size > 5 * 1024 * 1024) {
  showError('Файл слишком большой (макс. 5 МБ). Попробуйте уменьшить размер.');
  return;
}
```

### Тест-кейс

```
1. Загрузить маленький PDF (< 5 КБ, текстовый) → ОЖИДАНИЕ: Успех ✅ (подтверждено)
2. Загрузить реальный PDF-резюме (100–500 КБ) → ОЖИДАНИЕ: Текст извлечён
3. Загрузить повреждённый/пустой PDF → ОЖИДАНИЕ: "Не удалось извлечь текст"
4. НЕ ДОЛЖНО БЫТЬ: "Bad Gateway" или 502 ошибка
```

## 🟡 Замечание 3 (P3): VACANCY-TITLE-002 — Автозаполнение "Название должности" из имени резюме

### Описание проблемы

На странице /app/vacancy (вкладка "Ввести вручную") поле "Название должности" автоматически заполняется **именем загруженного резюме** (например, "OpenAI Test Resume"), а не извлечённой из текста должностью ("Product Manager").

Это развитие VACANCY-PLACEHOLDER-001 из V33 — теперь поле заполняется реальным значением (не placeholder), но значение **неправильное**.

### Причина

Фронтенд использует `resume.name` (имя файла/записи) вместо `resume.extracted_position` (извлечённая должность) при предзаполнении формы вакансии.

### Рекомендация

```typescript
// БЫЛО (предположительно):
setVacancyTitle(resumeData?.name || '');

// ДОЛЖНО БЫТЬ:
setVacancyTitle(resumeData?.extractedPosition || resumeData?.extracted_title || '');
```

Если поле `extractedPosition` пустое (парсер не нашёл должность), оставить поле пустым — пусть пользователь заполнит вручную.

### Тест-кейс

```
1. Загрузить резюме с текстом, содержащим "Product Manager / Менеджер продукта"
2. Перейти на страницу вакансии → "Ввести вручную"
3. ОЖИДАНИЕ: Поле "Название должности" = "Product Manager" (или пустое)
```

## Замечание 5 (P4): HH-RESUME-LINK-VALIDATION — Отсутствие клиентской валидации URL на вкладке "Ссылка hh.ru"

### Описание

На вкладке "Ссылка hh.ru" (`/app/upload`) поле ввода URL **не валидирует введённое значение** перед отправкой на сервер:

- Можно ввести любой URL (например, `https://google.com`) — запрос уйдёт на сервер
- Можно отправить пустое поле — запрос уйдёт на сервер
- Нет проверки формата hh.ru/resume/...

### Рекомендация

```typescript
// Добавить клиентскую валидацию перед отправкой:
const HH_RESUME_PATTERN = /^https?:\/\/(www\.)?hh\.ru\/resume\/[a-f0-9]+/i;

function handleSubmit(url: string) {
  if (!url.trim()) {
    showError('Введите ссылку на резюме');
    return;
  }
  if (!HH_RESUME_PATTERN.test(url)) {
    showError('Введите корректную ссылку на резюме hh.ru (формат: hh.ru/resume/...)');
    return;
  }
  // Отправить на сервер...
}
```

### Тест-кейс

```
1. Ввести пустое значение → ОЖИДАНИЕ: "Введите ссылку на резюме"
2. Ввести google.com → ОЖИДАНИЕ: "Введите корректную ссылку hh.ru"
3. Ввести hh.ru/resume/abc123 → ОЖИДАНИЕ: Запрос отправлен на сервер
```

## Замечание 7 (P4 INFO): HISTORY-MODEL-FORMAT-001 — Неконсистентный формат наименований в истории

### Описание

Записи в истории используют разные форматы:
- `openrouter:ai21/jamba-large-1.7` — provider:model ✅
- `openai:o4-mini-2025-04-16` — provider:model ✅
- `anthropic:claude-sonnet-4-6` — provider:model ✅

- `gigachat-pro` — только model ❌

Унифицировать формат заголовков: **"Provider Display Name · Model Name"**

Примеры:
- "GigaChat Pro · GigaChat-Pro"
- "OpenAI · o4-mini-2025-04-16"
- "Anthropic Claude · Claude Sonnet 4.6"
- "OpenRouter · AI21 Jamba Large 1.7"
- "Groq · Allam 2 7B"

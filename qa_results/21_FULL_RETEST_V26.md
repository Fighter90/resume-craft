## 4. Найденные проблемы

### 4.1 NAV-001 — «Обновить до Pro →» не реагирует на клик мыши ⚠️ REGRESSION

- **Severity:** P3 (Low)
- **Страница:** Sidebar (все страницы)
- **Описание:** Ссылка «Обновить до Pro →» в нижней части sidebar НЕ реагирует на физический клик мышью. Программный клик через JavaScript работает корректно.
- **Шаги воспроизведения:**
  1. На любой странице /app/* посмотреть sidebar внизу
  2. Кликнуть на ссылку «Обновить до Pro →»
  3. Ничего не происходит — навигация не срабатывает
- **Диагностика:**
  - `document.elementFromPoint(129, 693)` — возвращает корректный элемент `<a class="plan-upgrade" href="/app/settings/subscription">`
  - `element.click()` через JS — навигация работает ✅
  - `dispatchEvent(new MouseEvent('click'))` — `{hasOnClick: true, dispatched: false}` — обработчик вызывает preventDefault()
- **Вероятная причина:** Onclick handler на элементе вызывает `preventDefault()` и использует React Router's `navigate()`, но при физическом клике мышью React Router handler не срабатывает. Возможно, CSS overlay или z-index перекрывает элемент, или event listener не привязан корректно к DOM-элементу.
- **Рекомендация:** Проверить компонент sidebar — убрать preventDefault() если используется `<a href>`, или добавить `onClick` handler через React Router's `<Link>` компонент вместо обычного `<a>`.

### 4.2 EMAIL-VERIFY-001 — Противоречие верификации email 🔵 NEW

- **Severity:** P3 (Low / Cosmetic)
- **Страница:** /app/dashboard + /app/settings/profile
- **Описание:** На дашборде отображается жёлтый баннер «Подтвердите email qa_v25_test@example.com для полного доступа ко всем функциям», в то время как на странице Профиль поле Email показывает зелёную галочку с текстом «Подтверждён».
- **Шаги воспроизведения:**
  1. Войти под qa_v25_test@example.com
  2. На /app/dashboard видно баннер «Подтвердите email...»
  3. Перейти на /app/settings/profile
  4. Поле Email показывает «Подтверждён» с зелёной галочкой
- **Ожидаемое поведение:** Если email подтверждён — баннер на дашборде не должен отображаться. Если не подтверждён — Profile не должен показывать «Подтверждён».
- **Вероятная причина:** Разные источники данных для баннера и Profile. Баннер проверяет `user.email_verified` из JWT/сессии, Profile берёт данные из другого поля API. Одно из них неактуально.

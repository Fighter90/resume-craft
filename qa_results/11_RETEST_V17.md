## 🆕 Новые дефекты v1.7

### NEW-V17-001 — 🔴 CRITICAL: Кнопка «Найти» не отправляет API-запрос

**Severity:** CRITICAL
**Страница:** `/app/vacancy?resumeId=...` (вкладка «Поиск на hh.ru»)
**Шаги:**
1. Открыть резюме → Оптимизировать
2. Ввести запрос «Product Manager», город «Москва»
3. Нажать «Найти»

**Ожидание:** GET `/api/v1/vacancies/search?text=Product+Manager&area=1` → список вакансий
**Факт:** Клик на кнопку ничего не делает. Нет сетевого запроса, нет ошибок в консоли. Обработчик кнопки не подключён к API.

**Доказательство:**
- Ручной API-вызов `GET /api/v1/vacancies/search?text=Product+Manager&area=1` → 200 OK, возвращает реальные вакансии с hh.ru (title, company, salary, url)
- Кнопка не `disabled` (NEW-010 исправлен), но `onClick` handler не вызывает fetch/axios

**Workaround:** Использовать вкладку «Ввести вручную» — работает корректно.

### NEW-V17-002 — 🟠 HIGH: Оптимизированное резюме отображается как RAW JSON

**Severity:** HIGH
**Страница:** `/app/results/{task_id}`
**Шаги:**
1. Выполнить оптимизацию (Anthropic Claude Haiku 3)
2. Нажать «Посмотреть результат»

**Ожидание:** Форматированный текст резюме с секциями (ФИО, Опыт, Образование, Навыки)
**Факт:** Отображается RAW JSON:
```
{ "summary": "...", "experience": [...], "education": [...] }
```
**Причина:** Бэкенд возвращает `rewritten_data` как JSON-объект. Фронтенд не парсит его и выводит как строку.

### NEW-V17-003 — 🟠 HIGH: Match Score отображает 1% вместо реальных значений

**Severity:** HIGH
**Страница:** `/app/results/{task_id}` и `/app/export/{task_id}`
**API данные:**
```json
{
  "match_score_before": 0.601,   // 60.1%
  "match_score_after": 0.773     // 77.3%
}
```
**UI отображает:**
- Match Score: 1% (должно быть 77%)
- Улучшение: "+0 пунктов" (должно быть "+17 пунктов")
- Компоненты: все 1% (должно быть Keywords 40%, Experience 25%, Structure 20%, Readability 15%)
- Экспорт: "Match 1%" (должно быть "Match 77%")

**Причина:** Фронтенд не умножает десятичное значение (0.773) на 100, или ищет поле с другим именем. Компоненты не передаются из бэкенда или не парсятся.

### NEW-V17-004 — 🟠 HIGH: OpenAI o4-mini ошибка max_tokens

**Severity:** HIGH
**Страница:** `/app/processing` (при оптимизации через OpenAI)
**Ошибка:**
```
LLM-провайдер openai: Error code: 400 - {'error': {'message': "Unsupported parameter: 'max_tokens'
is not supported with this model. Use 'max_completion_tokens' instead.",
'type': 'invalid_request_error', 'param': 'max_tokens'}}
```
**Модель:** `openai:o4-mini`
**Причина:** Бэкенд передаёт параметр `max_tokens`, но модели серии `o*` (o1, o3, o4) требуют `max_completion_tokens`.
**Фикс:** При использовании моделей `o1*`, `o3*`, `o4*` заменять `max_tokens` на `max_completion_tokens` в API-вызове.

## Дополнительные находки

### Vacancy Search API

| Запрос | Статус | Комментарий |
|--------|--------|-------------|
| `GET /api/v1/vacancies/search?text=Product+Manager&area=1` | 200 ✅ | Возвращает реальные вакансии hh.ru |
| `GET /api/v1/vacancies/search?query=...` | 422 ❌ | Параметр `query` не поддерживается (должен быть `text`) |
| `POST /api/v1/vacancies/search` | 405 ❌ | Метод POST не поддерживается |
| `GET /api/v1/vacancies` | 404 ❌ | Эндпоинт не существует |

Фронтенд кнопки «Найти» вероятно использует неправильный URL или параметры.

- **OpenRouter** — доступен, 250+ моделей в dropdown

### Rate Limiting ✅

Подтверждено: 429 на 3-ю неудачную попытку логина. Ранее rate limiting отсутствовал.

### Профиль

### NEW-V18-002: Прогресс-бар оптимизации застревает на 0%

| Поле | Значение |
|------|----------|
| **Severity** | 🟡 MEDIUM (P2) |
| **Компонент** | Frontend — Processing Page (/app/processing) |
| **Ожидание** | Прогресс-бар обновляется в реальном времени по мере выполнения оптимизации (0% → 25% → 50% → 75% → 100%) |
| **Факт** | Прогресс-бар показывает 0% в течение ~23 секунд, затем резко перескакивает на 100% «Оптимизация завершена!». При этом API `/api/v1/rewrite/{id}/status` уже давно возвращает `"status":"completed","progress":100`. |
| **Воспроизведение** | 1. Запустить оптимизацию через Anthropic Claude → 2. Наблюдать страницу /app/processing → 3. Прогресс-бар застывает на 0% → 4. Через ~23 сек скачок на 100% |
| **Влияние** | UX-дефект. Пользователь не понимает, идёт ли процесс. Может решить, что оптимизация зависла, и перезагрузить страницу. |
| **Вероятная причина** | Frontend polling интервал слишком большой, или WebSocket не обновляет прогресс-бар промежуточными значениями. |

### Средний приоритет:

4. **NEW-V18-002 — Прогресс-бар**: Не обновляется промежуточными значениями.
   - **Fix:** Уменьшить polling interval или реализовать Server-Sent Events (SSE) для прогресса.
